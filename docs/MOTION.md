# 可选板载摇动触发

本版本为 AtomS3R-CAM 添加一个保守的阈值输入，复用现有 `haptic::Player` 和 `button_pattern`。它不生成音乐、不学习个人动作模型、不识别脸/头/打响指，也没有实物准确率结果。

## 使用

1. 选择 `m5atoms3r_cam` 或 `m5atoms3r_cam_u059` 构建，按对应接线连接驱动/马达。没有马达时只能看串口事件，不能感到振动。
2. 输入 `arm`。第一次会初始化官方 IMU 驱动；播放过程中拒绝 arm，先 `stop`。
3. 静置至少 2 秒，等待 `motion armed`。10 秒内无法完成静置，或传感器状态异常，会回到 `off`。
4. 做一次明显来回摇动。检测到后，串口输出 `imu-shake <pattern> started`；所有振动仍受 Player 的时长、busy、冷却与停止规则控制。
5. 放回包里前输入 `disarm`；重启默认关闭。`stop` 同时停止马达和解除动作检测。

## 规则与边界

内部 I²C 为 **SDA GPIO45 / SCL GPIO0**，BMI270 地址 **0x68**。该总线不同于 Grove 的 GPIO1/2，也不占用摄像头或 Atomic Voice Base 引脚。驱动复用 M5Unified `IMU_Class` / `I2C_Class`，不调用全设备 `M5.begin()`。初始化后还单独读回 Bosch `INTERNAL_STATUS` 的 `INIT_OK`，不只相信库函数的成功返回。旧应用在 NVS 中的偏移值仅在当前 RAM 中清除；不保存新的 NVS 校准值。

只读取具有新鲜 accelerometer 标志的样本用于判断，按 20 ms 间隔尝试读取。动作检测变量都在 RAM，未保存/上传原始传感器样本。官方驱动会配置 BMI270 及辅助磁力计，但本应用的判断仅使用加速度。

设 `g0` 为静置样本的平均加速度模长，`d = |sqrt(ax² + ay² + az²) - g0|`。算法在 [shake_detector.h](../include/shake_detector.h)：

| 阶段 | 条件 |
| --- | --- |
| 静置基线 | ≥2 s 且 ≥50 个样本；模长 0.85–1.15 g，向量距起点不超过 0.08 g；移动则重新累计 |
| 摇动峰值 | `d ≥ 0.75 g` 至少持续 20 ms；单个样本尖峰不算 |
| 两峰分离 | 中间 `d ≤ 0.25 g` 至少 40 ms，两个上升沿相隔 80–600 ms；持续高值不算两个峰 |
| 触发后 | 检测器至少抑制 2 s，然后要求 ≥500 ms 安静；Player 自己的结束后冷却仍保留 |
| 马达运行 | 暂停 I²C 读取和峰值累计；运行结束后要求 ≥500 ms 安静；校准中播放会取消本次校准 |
| 异常 | 无新鲜读数 ≥100 ms、有效样本间隔不在 5–100 ms、时间倒退/重复、NaN/Inf、轴接近 ±8 g 饱和、模长 <0.2 g，均解除检测 |

这是起始参数，不是经过用户实验验证的舒适/准确阈值。它可能把某些快速携带、敲击或跌落识别成摇动；开启状态应限于主动交互时段。设备朝向变化本身通常不改变模长，所以缓慢转身/点头不是此版本的功能。停止检测不会自动关闭 IMU 芯片电源；只停止本应用读取和动作判断。

## 证据

- 桌面用同一 `ShakeDetector` 注入合成 g 样本；测试默认关闭、静置超时、轻微抖动、转向、单尖峰、持续加速、两峰、抑制/沉降、停止/冷却、无效/陈旧样本和时钟回绕。
- 固件编译证明官方库 API 和目标板构建兼容，不能证明本机 IMU 总线通信、阈值准确率或马达机械隔离已通过。
- 接实物后至少记录：静置校准成功率；20 次主动摇动的成功数；20 次拿起/放下/走路/放包的误触发；播放后的自触发；断开/故障后是否回 `off`。不要在开启模式下故意跌落设备。

官方依据：[M5 CAM 引脚与 BMI270](https://docs.m5stack.com/en/core/AtomS3R%20Cam)、[M5Unified 0.2.7 IMU 实现](https://github.com/m5stack/M5Unified/blob/0.2.7/src/utility/IMU_Class.cpp)、[Bosch BMI270 状态定义](https://github.com/boschsensortec/BMI270_SensorAPI/blob/master/bmi2_defs.h)。
